4.1 · SEQUENCE & ERROR HANDLING

ลำดับการทำงานและ error codes

① UI

เจ้าหน้าที่กดประเมิน

② Validate

schema + business rules

③ Predict

pipeline → PD, band

④ Explain

SHAP top-k reasons

⑤ Log → UI

200 + feedback → 201

HTTPerror.codeเมื่อไร
422VALIDATION_ERRORขาดฟิลด์, enum ผิด, ค่านอกช่วง (บอก field + issue)
400BUSINESS_RULE_VIOLATIONข้อมูลขัดแย้ง เช่น ค่างวดมากกว่าวงเงิน
400MALFORMED_JSONbody ไม่ใช่ JSON ที่ถูกต้อง
413BATCH_TOO_LARGEbatch เกิน 100 คำขอ
503MODEL_UNAVAILABLEโหลดโมเดลไม่ได้ → ใช้กระบวนการ manual
ลำดับการทำงานเป็นแบบนี้ UI ส่ง request มา API ตรวจ schema และ business rule ถ้าผิดจะตอบ error ทันที ถ้าผ่านจะส่งเข้า pipeline เพื่อทำนาย ส่งต่อ explainer เพื่อสร้างเหตุผล บันทึก log แล้วตอบกลับ UI เมื่อเจ้าหน้าที่ส่ง feedback จะได้ 201 ทุก error ใช้รูปแบบเดียวกัน คือมี code, message และ details แยก 422 สำหรับข้อมูลผิดรูปแบบ กับ 400 สำหรับข้อมูลที่ขัดแย้งกัน และ 503 เมื่อโมเดลไม่พร้อม ซึ่งหน้า UI จะแจ้งให้ใช้กระบวนการ manual sequence diagram แบบเต็มอยู่ในรายงานหัวข้อ 4.1
