3.3 · MLFLOW TRACKING UI

เลือกโมเดลด้วยกฎ 3 ขั้น ไม่ใช่ AUC อย่างเดียว

1 · Calibration gate

Brier ≤ 1.10 × ตัวที่ดีที่สุด → ตัด v3

2 · Discrimination

ROC-AUC สูงสุด โดยต่างกัน ≤ 0.003 ถือว่าเท่ากัน → v5, v6

3 · Fairness → latency

gender FPR gap ต่ำสุด → เลือก v6_hgb_tuned_reweighed

ทุก run log params, metrics, fairness CSV และ model · 5-fold CV ของตัวที่เลือก 0.756 ± 0.005

นี่คือ MLflow Tracking UI จริง เทียบทั้ง 6 run ใน 4 metric หลัก การเลือกโมเดลใช้กฎ 3 ขั้นที่เขียนไว้ในโค้ด ขั้นแรกคือ calibration gate ตัดโมเดลที่ความน่าจะเป็นเพี้ยน ขั้นที่สองเลือก AUC สูงสุด โดยถือว่าต่างกันไม่เกิน 0.003 คือเท่ากัน ขั้นสุดท้ายใช้ fairness ตัดสิน ได้ v6 ผล cross-validation 5 fold ได้ 0.756 บวกลบ 0.005 แสดงว่าโมเดลเสถียร
