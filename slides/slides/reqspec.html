2.2.2 · AI TASK REQUIREMENTS

ENV ∧ SPEC ⊨ REQ

REQ · โลกจริง

  • สินเชื่อที่อนุมัติผิดนัดน้อยลง
  • ไม่เลือกปฏิบัติตามเพศหรืออายุ
  • ผู้กู้ได้รับเหตุผลที่เข้าใจได้
  • มนุษย์ตัดสินใจขั้นสุดท้าย

SPEC · ระบบ

  • คืน PD + band ภายใน 300 ms
  • ROC-AUC ≥ 0.75 บน test set
  • ไม่ใช้ gender เป็น feature
  • คืนเหตุผล top-k ทุก prediction
  • input ผิด → 422, ขัดแย้ง → 400

ENV · สมมติฐาน

  • ข้อมูลที่กรอกตรงกับเอกสาร
  • ผู้กู้ใหม่คล้ายข้อมูลในอดีต
  • มีคะแนน bureau ส่วนใหญ่
  • เจ้าหน้าที่ตรวจเคส REVIEW/HIGH จริง

รายงานมีครบ REQ-1…4, SPEC-1…8, ENV-1…5 · ENV-5: มี label เฉพาะคนที่เคยได้รับอนุมัติ (selection bias)

หัวข้อ 2.2.2 ใช้กรอบ REQ, SPEC, ENV ความคิดหลักคือ ถ้าสมมติฐานเรื่องสภาพแวดล้อมเป็นจริง และระบบทำงานตาม spec ความต้องการในโลกจริงก็จะเป็นจริง ตัวอย่างเช่น REQ ว่าไม่เลือกปฏิบัติตามเพศ จับคู่กับ SPEC ว่าไม่ใช้ gender เป็น feature ซึ่งผมทดสอบจริงในส่วน interface testing ส่วน ENV สำคัญคือเจ้าหน้าที่ต้องตรวจเคสเสี่ยงจริง ถ้าข้อนี้ไม่เป็นจริง ระบบจะเสี่ยง ซึ่งจะเห็นอีกครั้งใน fault tree
