4.2 · CHALLENGES & SOLUTIONS

ปัญหาที่เจอจริงระหว่างพัฒนา

ปัญหาวิธีแก้
โมเดล class-weighted ให้ PD เฉลี่ย ~41% (จริง ~9%)เพิ่ม calibration gate (Brier) ในการเลือกโมเดล
JSON เสียได้ 422 เหมือน validation errorcustom handler แยกเป็น 400 MALFORMED_JSON
ข้อมูลผ่าน schema แต่ไม่สมเหตุผลbusiness-rule layer → 400 พร้อมรายการฟิลด์
SHAP ของ one-hot อ่านยากรวมกลับเป็นฟิลด์เดิม + label ภาษาไทย
UI ส่งหน่วย “ปี” แต่ train ใช้ “วันติดลบ”แยก raw → applicant และใช้ pipeline ร่วมกัน
เก็บเพศเพื่อ audit แต่ห้ามใช้ทำนายรับใน request แล้วตัดทิ้งก่อนเข้าโมเดล + ทดสอบ S4
ปัญหาที่เจอจริงระหว่างพัฒนามีหลายข้อ ข้อที่สำคัญที่สุดคือโมเดลที่ใช้ class weight ให้ความน่าจะเป็นเฉลี่ยถึง 41% ทั้งที่อัตราจริงราว 9% ถ้าใช้โมเดลนี้ หน้าจอจะแสดงตัวเลขที่ผิดให้เจ้าหน้าที่ ผมจึงเพิ่ม calibration gate ข้ออื่น ๆ เป็นเรื่อง API เช่น แยก error JSON เสียออกจาก validation error เพิ่ม business rule สำหรับข้อมูลที่ขัดแย้งกัน และรวม SHAP ของ one-hot ให้อ่านง่าย รวมถึงปัญหาหน่วยไม่ตรงกันระหว่างตอน train กับตอนใช้งาน
